# Master-prompt compliance audit

- Review date: 2026-07-30
- Project owner and publisher: Annas M. Ishtiaq
- Scope: the repository, built application, automated evidence, operating
  documentation, and deployment state
- Authority: the master build prompt plus the owner's three overriding rules

This is the criterion-by-criterion record requested by the owner. It separates
implemented evidence from ambition and from work that needs an external
deployment, device, scientific, legal, or accessibility review. A feature name
or test file is not counted as a pass by itself.

## Status key

- **Met** — repository evidence implements the criterion within the explicitly
  bounded release scope.
- **Partial** — useful implementation exists, but one or more literal
  requirements or assurance steps remain.
- **Not applicable** — the architecture deliberately removes the relevant
  runtime surface, with the reason recorded.
- **Externally blocked** — local work is done, but the remaining action requires
  a separate authority, service, person, device, or production environment.

## External and specialist constraint register

The repository cannot honestly manufacture these results:

1. **Source upload and hosted deployment.** No source or release archive may be
   transmitted without explicit authorisation from Annas M. Ishtiaq. After
   authorisation, the operator must create/verify separate preview and staging
   boundaries, preserve owner-only production access, save immutable versions,
   deploy, poll to terminal status and complete the hosted addendum.
2. **Protected environment settings.** Required reviewers, branch protection,
   secret scanning and push protection are repository-host controls.
3. **Manual accessibility.** Screen readers, browser zoom/reflow, contrast,
   switch/voice input and physical touch devices require humans and actual
   assistive technologies.
4. **Device/GPU performance.** Representative low-end and modern hardware,
   thermal/power states, long-duration frame-time/GPU-memory captures and
   physical gamepads cannot be inferred from emulation.
5. **Scientific/legal sign-off.** Automated provenance and schema checks do not
   replace qualified review of interpretation, licences and reciprocal
   obligations.
6. **Inactive storage operations.** Hosted backup/restore/migration/load tests
   cannot run until the owner approves and provisions a storage binding.

## Release decision

The repository is a functioning, test-backed, scientifically labelled
educational release with a reproducible local and candidate-packaging path. It
must not be represented as satisfying every literal master-prompt ambition.
The principal remaining engineering scope is advanced renderer/streaming work;
the principal remaining release scope is an explicitly authorised hosted
preview, staging rehearsal and production promotion.
